# M3 – Text and PDF import

Branch: `m3-import`. References: `PLAN.md` (M3), `PROMPT.md` §4 (write order), §5 (import pipeline), §7 (Import screen), §8 (performance), the `pdf-import-pipeline` and `audiobook-storage` skills (`.claude/skills/`), the `modular-architecture` skill §2–§6, §9–§10, the mockup `.claude/design/02-import-pdf.png`.

## Goal

A PDF picked from the phone becomes a book in storage, fully offline: the text is extracted page by page by pdf.js in a hidden WebView, cleaned, segmented into Romanian sentences and split into chapters by pure functions in `services/text`, and saved chapter by chapter through the M2 `BookRepository`. The first chapter is playable before the import ends, a killed app resumes the import, and scanned, protected, corrupt or cancelled imports leave no data behind. The Library list and the player are M4/M5; M3 only produces the stored book and the Import screen.

## Corrections to `PLAN.md` (reported, fixed in the plan commit)

1. **pdfjs-dist 6.5 is ESM only.** `legacy/build/` has only `pdf.mjs` and `pdf.worker.mjs`; there is no UMD file to drop into a `<script>`. "The worker inlined" means a build-time step that produces one self-contained HTML (pdf.js as a module script, the worker as a blob URL or through `workerPort`). The exact form is decided by the spike in step 7.
2. **`services/pdf` doesn't touch the file system.** `WebViewPdfExtractor` receives a `readChunk(offset, length) → base64` function, bound in `app/dependencies.ts` over a new `FileStore.readBase64`. So `services/pdf` stays storage- and Redux-free, and the lint rule "FS only in `storage/` and `repositories/`" holds without an exception.
3. **Missing primitives.** The import form needs a text field (title, author) and a select (voice language), which M1 didn't build. `TextField` and `Select` go into `shared/ui`, with the `abook://dev/ui` catalog and a11y tests, like the other primitives.
4. **Boot.** M2 marks every `processing` book `failed` at boot (`failInterruptedImports`). M3c replaces that with resuming from `processedPages`, as already noted in the M2 decisions; only a book that can't be resumed (missing PDF, invalid meta) still becomes `failed`.

## Decisions (assumptions; I report them if they change)

- **Header/footer statistics vs. streaming.** The skill's rule ("repeats on ≥ 50% of pages") needs all pages, but the import saves chapter by chapter. Header and footer candidates are computed on a sample window (the first ~20 pages, or all of them if fewer), then applied to every page. A resumed import recomputes them from the same window, so the result is the same as an uninterrupted import.
- **`processedPages` = the end page of the last saved chapter**, not the last extracted page. Resume restarts at the first page of the next chapter and never re-splits a saved chapter. The progress bar in the UI uses the extracted page (in the slice), not `processedPages`.
- **Chapter source is chosen once, at open:** the PDF outline gives the page ranges up front; otherwise headings (short line, larger height, `^(Capitolul|Partea|CAPITOLUL|[IVXLC]+\.?)\b`) are detected while streaming; otherwise a chapter every ~10 pages. A resumed import uses the same source.
- **The import starts as soon as a file is picked**, as in the mockup (extraction runs while the form is editable). "Adaugă în bibliotecă" writes title / author / language into `meta` and closes the modal; processing continues in the background, driven by a thunk, not by the screen.
- **Duplicate fingerprint:** file size + SHA-256 of the first 64 KB (`@noble/hashes`, which probably needs `ESM_PACKAGES` in Jest). It is stored in `BookMeta`, so the schema changes → migration `002` (idempotent, as required by the M2 runner) that leaves old books without a fingerprint.
- **Test PDFs** are generated by a script (a 300+ page text PDF with Romanian text, repeated headers and page numbers; an image-only "scanned" PDF; a password-protected one; a truncated/corrupt one). They live outside the app bundle and are pushed to the emulator; they never ship in a release build.
- **Yielding:** the pipeline awaits between batches of 5 pages and between cleanup/segmentation batches, so the JS thread stays free. Parsing happens only in the WebView.

### M3a – `services/text` (pure functions, one per file)

`jest.config.js` gets a 100% coverage threshold for `src/services/text/**`.

#### 1. Branch, skills, plan
- `git switch -c m3-import` from `dev`; load `modular-architecture`, `pdf-import-pipeline` and `audiobook-storage`.
- This plan + the corrections in `PLAN.md` (M3 section, risks).
- **Check:** the branch starts from `6b63561`.

#### 2. Page types, headers and page numbers
- `services/text/types.ts`: `PageLine { text, y, height }`, `PageText { page, lines }` (the shape the WebView returns), `PageHeight` if the band needs it.
- `stripRepeatedHeaders(pages, sample)` (top/bottom band, digits replaced before comparing, ≥ 50% of the sample), `stripPageNumbers` (isolated numbers, `- 12 -`, `12 / 300`, Roman numerals alone on a line).
- **Tests:** table-driven with a book header + chapter header, footers with changing page numbers, a line that repeats in the middle of the page (kept), < 2 pages, empty pages.

#### 3. Hyphenation and normalization
- `joinHyphenatedWords` (`cuvân-\ntul` → `cuvântul` only when the hyphen ends a line and the next line starts lowercase; keeps `d-na`, `într-o` mid-line, and a hyphen before an uppercase word).
- `normalizeDiacritics` (ş ţ Ş Ţ cedilla → ș ț Ș Ț comma below, collapsed whitespace, NBSP, soft hyphen removed).
- **Tests:** Romanian samples with both diacritic forms, compound words (`nord-est`), line-final hyphen before uppercase, empty text.

#### 4. Sentence segmentation
- `segmentSentences(text)` on `.` `!` `?` `…` followed by space + uppercase or a dialogue dash; not after the abbreviations (dl., dna., d-na, nr., pag., p., vol., cap., etc., ș.a., ș.a.m.d., prof., dr.) or initials (`I. L. Caragiale`); „…” quotes and `?!` stay with their sentence. The abbreviation list is a constant in its own file.
- **Tests:** dialogue with `—` and `–`, nested quotes, abbreviations at the end of a real sentence, initials, numbers (`3.5`, `1.000`), ellipsis mid-sentence, empty / whitespace-only text.

#### 5. Long sentences
- `splitLongSentence(sentence, maxChars = 400)`: cut at the `;` or `,` closest to the middle, recursively; if there is none, at the space closest to the middle; never mid-word. Every part ≤ `maxChars` (the M2 chapter splitter relies on it).
- **Tests:** 401 / 399 characters, only commas, no punctuation, one giant word, idempotence on short sentences.

#### 6. Chapters and chunks
- `detectChapters` in three files by source: `chaptersFromOutline`, `detectHeadingChapters` (regex + line height above the page median), `fixedPageChapters` (~10 pages); plus `buildChapterChunk(pages)` → `{ sentences, sentencePages }` validated against the M2 `ChapterChunk` schema, and `toChapter` for the `toc` entry.
- **Tests:** outline with nested entries and missing pages, headings in Roman numerals, a "Capitolul" inside a paragraph (not a heading), a PDF with no headings, a sentence that spans a page break (gets the page where it starts).

### M3b – `services/pdf`

#### 7. Spike: pdf.js in a WebView (throwaway)
- Answers the two open rows of the risk table: legacy pdf.js 6.5 with its worker inside a WebView on Android, and where the HTML lives in RN CLI (an Android `assets/` file + the iOS bundle, vs. an inline string generated at build time and passed as `source={{ html }}`).
- Also checks: `originWhitelist`, no network (`INTERNET` exists only in debug, so a release build proves it), message size limits, speed on a 300+ page PDF.
- **Check:** text from page 1 of a real PDF arrives in RN on the emulator. The spike code is discarded; the decision and numbers are recorded here.

#### 8. WebView build and bridge protocol
- A build script (in `.claude/scripts/` or `scripts/`) that produces the self-contained HTML from `services/pdf/webview/` sources + `pdfjs-dist`; the output is checked in or generated before Metro, as the spike decides. A test fails if the generated file is stale.
- `services/pdf/protocol/`: message schemas `{ type, requestId, payload }` (zod) for `load-chunk`, `open`, `get-pages`, `get-outline`, `close` and the responses/errors; the same validation runs inside the WebView.
- `RequestTracker`: per-request timeout, cancel, late or unknown responses dropped. Pure, tested with fake timers.

#### 9. `FileStore.readBase64`
- `readBase64(path, offset, length)` over RNFS `read(…, 'base64')`, in the adapter, `InMemoryFileStore` (which now stores bytes, not only sizes, or a seeded content) and the jest mock; the contract suite covers it. Chunks are 512 KB.
- **Tests:** reading across the end of the file, offset past the end, missing file rejects.

#### 10. Extractor and host
- `PdfTextExtractor` interface (`open(uri) → { pageCount, info }`, `getPages(from, to)`, `getOutline()`, `close()`), `WebViewPdfExtractor` (sends the file in chunks, batches of 5 pages, typed errors: `password`, `corrupt`, `timeout`, `cancelled`), `FakePdfTextExtractor` in `services/pdf/testing/`.
- `app/providers/PdfExtractorHost`: mounts the WebView once, hidden, and hands it to the extractor; wiring in `dependencies.ts` (`AppDependencies` gets `pdfExtractor`).
- **Tests:** the extractor against a fake WebView transport (chunking, batching, error mapping, cancel mid-batch).

#### 11. Emulator check of the extractor
- Dev route `abook://dev/pdf` (`__DEV__` only, like `dev/ui` and `dev/storage`): opens a generated 300+ page PDF, shows pages/s and the cleaned text of a chosen page, and a counter that keeps ticking to prove the JS thread is free.
- **Check:** the whole PDF extracts without a red screen or a freeze; password and corrupt PDFs give the typed errors.

### M3c – `features/import`

#### 12. Import state machine
- `features/import/state/importSlice.ts`: `idle | copying | opening | extracting(page, total) | saving | ready | failed(reason) | cancelled` + the picked file info and the form; pure transitions (an invalid transition is ignored and logged), memoized selectors for the step list.
- **Tests:** every transition, invalid ones, the derived step statuses (done / in progress with page X/Y / waiting / error).

#### 13. Pipeline thunk (happy path)
- `services/` inside the feature: `runImport` orchestrates, one capability per file: copy (`storePdf`) → `createBook` (`processing`) → open → batches of 5 → clean → segment → chapters → `saveChapter` for each completed chapter (+ `processedPages`) → `saveToc` → `meta` `ready`. Title/author prefill from the PDF info.
- **Tests (fake extractor + M2 fakes):** the exact write order, the first chapter is readable while extraction continues, the library slice gets the book (`bookUpserted`), yields between batches.

#### 14. Failure cases and duplicates
- Scanned (each of the first 5 pages < 20 characters), password, corrupt, timeout, cancellation: each ends in `failed(reason)` / `cancelled` with **no keys and no file left** (`deleteBook`).
- Duplicate: fingerprint (`@noble/hashes`) compared with the existing books; the user is asked before importing a copy. `BookMeta.fingerprint` + migration `002` with its test.
- **Tests:** one per case, asserting the fakes are empty afterwards; the duplicate prompt; the migration (idempotent).

#### 15. Resume at boot
- A `processing` book with its PDF present resumes from `processedPages` after `PdfExtractorHost` is mounted; without the PDF, or with an invalid meta, it becomes `failed` (the M2 behavior). `failInterruptedImports` is narrowed accordingly.
- **Tests:** crash after chapter 2 → boot → the import continues from chapter 3 and the result equals an uninterrupted import.

#### 16. `TextField` and `Select` primitives
- `shared/ui/TextField` (label, value, error, a11y label) and `shared/ui/Select` (label, options, opens a list; role and state), on tokens, ≤ 7 props, in the `abook://dev/ui` catalog.
- **Tests:** render, typing / choosing, accessibility state, font scaling.

#### 17. Import screen
- Per `02-import-pdf.png`: file card (name, size, pages) + "Schimbă", "Procesare locală" step list (copy / extract with page X/Y and bar / chapters and sentences / save), "Detalii carte" form, "Adaugă în bibliotecă" + the note. States: per-step error, scanned, duplicate, cancellation. Texts in `ro.json`.
- Picker: `@react-native-documents/picker` with `types.pdf`, the 100 MB limit (a constant), and the `content://` question from M2 step 4 (`keepLocalCopy` vs. a direct `copyFile`) answered on the emulator.
- **Tests:** each state from the screens table with a fake pipeline; the screen stays ≤ 120 lines (sections in components).

#### 18. Emulator verification
- A real 300+ page PDF imports without freezing the UI; the first chapter is readable (dev storage screen) before the end; kill mid-import → relaunch → it resumes; scanned / protected / corrupt PDFs show clear messages and leave nothing (`adb shell run-as com.abook ls files/books`, key count on `abook://dev/storage`).
